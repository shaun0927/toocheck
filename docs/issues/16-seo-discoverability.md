## 0. 배경 — 진단 요약

페이지 단위 SEO(메타·OG·h1·시맨틱)는 잘 돼 있으나, **"검색엔진이 들어와서 모든 페이지를 발견하는" 인프라가 통째로 빠져** 있다. 핵심 발견:

| 영역 | 현재 | 영향 |
|---|---|---|
| **robots 색인** | `app/layout.tsx` 에 `robots: { index: false, follow: false }` | 🔴 **전 페이지 색인 차단** — 다른 모든 작업의 선결 차단막 |
| 사이트맵 | 없음 (`app/sitemap.ts` 부재) | 🔴 8,800여 페이지 발견 경로 없음 |
| 크롤 도달성 | 홈 링크로 닿는 건 대표 지역 1곳 + 하드코딩 후보 1명뿐 | 🔴 나머지 2,091 선거구·6,700여 후보 링크 고립 |
| robots.txt | 없음 | 🟡 사이트맵 위치·크롤 정책 미고지 |
| 검색엔진 등록 | 구글 서치콘솔·네이버 서치어드바이저·빙 모두 미등록 | 🔴 색인 요청·모니터링 불가 |
| 구조화 데이터 | JSON-LD 전무 | 🟡 리치결과·AI 인용 기반 없음 |
| 페이지별 메타데이터 | `generateMetadata`로 동적 생성 (양호) | 🟢 유지 |
| canonical | 없음 | 🟡 `?sort=` 중복 신호 방어 안 됨 |

### 한국 검색 환경 (왜 구글만으론 부족한가)

- 네이버 ~63% / 구글 ~30% / 빙·다음 각 ~3% (2026, Internet Trend 기준).
- 네이버 크롤러(Yeti)는 **신규 사이트를 자동으로 안 긁음** → 서치어드바이저 수동 등록 + XML 사이트맵 제출(사이트당 1개) 필수.
- 한국 사용자의 절반 이상이 ChatGPT를 검색용으로 사용 + 네이버 Cue:(HyperClova X) → **AI 인용(GEO)도 별도 전선**. toocheck은 사실·출처·기준일이 명확한 정형 데이터라 GEO에 유리.

### ⏰ 시의성

오늘 기준 제8회 전국동시지방선거 투표일이 임박(2026-06-03). 검색 수요는 지금~선거일에 폭증하나, 신규 사이트가 8,800 페이지를 그 안에 완전 색인시키긴 어렵다(특히 네이버). 따라서 **"전부 색인"이 아니라 "차단 해제 + 고가치 페이지 우선 색인 + AI 인용 대비"** 로 우선순위를 좁힌다. 동시에 본 작업은 보궐·차기 선거·역사 기록용 **장기 자산**이므로 끝까지 갖춰둘 가치가 있다.

## 1. 공통 안전 수칙 (모든 작업 PR에 강제) ⭐️

> 사용자 요구: **"각 작업 진행 시 사이트 내용이 깨지거나 작동하지 않으면 안 된다."** 아래는 전 작업 공통 게이트다.

1. **동적/정적 경계를 바꾸지 않는다 (기본값).**
   `/candidates/[id]`·`/districts/[id]`·`/districts/[id]/compare`는 #70에서 **의도적으로 동적(ƒ)** 이다. SEO-8(SSG 전환)을 제외한 모든 작업은 이 경계를 건드리지 않는다.
2. **네이티브/무거운 의존성을 페이지·레이아웃·공용 컴포넌트 import 그래프에 들이지 않는다.**
   `satori`·`@resvg/resvg-js`·`fs` 폰트 로드는 #64→#69에서 **메타데이터 렌더 경로를 오염시켜 Vercel에서만 크래시**시킨 전력이 있다. JSON-LD(SEO-6)는 순수 문자열이라 안전하지만, **이미지 생성 코드를 다시 끌어오지 않는다**.
3. **`mocks/loader`는 서버 전용으로만 import** (`'use client'` 파일에서 금지). 13MB JSON이 클라이언트 번들로 새지 않게.
4. **빈칸 원칙 준수.** 메타·구조화 데이터에서 비어있는 필드는 **생략**한다(추정·날조 금지). 교육감 정당 공란(R1), 기초의원 5대공약 비대상(R3) 등 직책별 분기에서 `undefined`로 throw하지 않도록 가드.
5. **로컬 + Vercel Preview 이중 검증.** "로컬은 되는데 Vercel만 깨지는" 버그 클래스([#70 §7]) 때문에 **각 PR은 Vercel 프리뷰 배포에서 후보·지역·비교·홈 4개 경로를 소프트 내비게이션(클릭 이동)으로 직접 확인**한 뒤 머지한다. (콘솔에 `An error occurred in the Server Components render` / `net::ERR_ABORTED` 없을 것.)
6. **회귀 가드.** `pnpm typecheck && pnpm lint && pnpm build && pnpm test` 통과를 PR 머지 조건으로 한다. `pnpm e2e` 골든패스가 깨지지 않아야 한다.
7. **단일 책임 PR + 즉시 롤백 가능.** 각 작업은 독립 revert가 가능하도록 파일 단위를 분리한다(아래 각 작업의 "롤백" 참조).

### 🔴 SEO-1 — 색인 차단 해제 + canonical 기본값 + 검증 메타 골격  (P0)

**목적**: 검색엔진이 색인할 수 있게 하고, 소유권 인증·중복 방지의 골격을 메타데이터 레벨에서만 마련. **런타임 코드 0, 위험 최저.**

**변경 파일**: `app/layout.tsx` (metadata 객체만)

**구현 상세**:
- `robots`를 `{ index: true, follow: true }` 로 전환. 단, 비공개 유지 경로(`/correction`, `/correction/thank-you`, `/preview`, `/api/**`)는 해당 라우트의 `metadata`에서 개별적으로 `robots: { index: false }` 또는 robots.txt(SEO-2)에서 Disallow로 유지.
- `alternates: { canonical: './' }` 기본 패턴 추가(루트). `metadataBase`가 이미 있으므로 상대경로 canonical이 페이지별로 올바르게 해석됨. (동적 라우트의 per-page canonical은 SEO-4에서 보강.)
- `verification: { other: { 'naver-site-verification': '<TODO>' } }` + 구글은 서치콘솔 메타 또는 DNS. 값은 SEO-3에서 발급 후 주입 — **자리만 환경변수/상수로 마련**(빈 값이면 태그 미출력하도록 가드).

**안전장치 — 건드리지 않는 것**:
- 페이지 컴포넌트·렌더 로직·라우팅 일절 미변경. **순수 메타데이터 객체만 수정.**
- 비공개 경로의 noindex 의도 보존(위 목록).

**검증**:
- `pnpm build` 후 `/`, `/districts`, `/candidates/100157144`, `/districts/dist_3_3110000/compare` 의 `<head>`에 `robots` 메타가 `index,follow`로, 비공개 경로는 `noindex`로 나오는지 확인.
- Vercel 프리뷰에서 4개 경로 소프트 내비게이션 정상.

**롤백**: `app/layout.tsx` 한 파일 revert.

**DoD**: 공개 경로 indexable, 비공개 경로 noindex 유지, 빌드/타입/린트/테스트 통과, 프리뷰 정상.

**위험도**: 🟢 매우 낮음 (메타데이터 only).

### 🔴 SEO-2 — `robots.ts` + `sitemap.ts` 생성  (P0)

**목적**: 크롤러에 사이트맵 위치·크롤 정책을 고지하고, 8,800여 URL 전체를 사이트맵으로 노출.

**변경 파일**: `app/robots.ts` (신규), `app/sitemap.ts` (신규). 기존 파일 미변경.

**구현 상세**:
- `app/robots.ts` — `MetadataRoute.Robots` 반환:
  ```
  rules: [{ userAgent: '*', allow: '/', disallow: ['/api/', '/correction', '/preview'] }]
  sitemap: `${SITE.url}/sitemap.xml`
  host: SITE.url
  ```
  (네이버 Yeti도 이 `sitemap:` 줄을 읽음.)
- `app/sitemap.ts` — `MetadataRoute.Sitemap` 반환. **서버 전용 loader 순회**로 URL 생성:
  - 정적: `/`, `/districts`, `/principles`.
  - 선거 순회: `listElections()` → 각 `listDistricts(electionId)` → `/districts/{id}`, `/districts/{id}/compare`.
  - 후보 순회: 각 지역의 `listCandidates(districtId)` → `/candidates/{id}`.
  - `lastModified`: 지역은 `getDistrictSourceCheckedAt(id)` 사용(없으면 site-data `generatedAt` 폴백). 구글은 `priority`/`changefreq` 무시하므로 `lastModified` 정확도에 집중.
- 규모: 총 ~8,800개로 **5만 URL/50MB 한도 이내 → 단일 사이트맵 가능.** 향후 초과 시 `generateSitemaps()`로 분할(주석으로 경로만 남겨둠).

**안전장치 — 건드리지 않는 것**:
- loader는 **이미 서버에서 쓰이는 순수 함수** — 신규 import도 서버(메타데이터 라우트)에서만. 네이티브 의존성 0.
- 페이지 렌더·데이터 미변경. 사이트맵은 별도 라우트라 페이지 import 그래프와 무관.

**검증**:
- `pnpm build` 빌드 시간 측정(8,800 순회가 빌드를 과도하게 늘리지 않는지 — 동적 `sitemap.ts`면 요청 시 생성이라 빌드 영향 미미, 확인).
- 로컬 + 프리뷰에서 `/sitemap.xml`·`/robots.txt` 200 응답, XML 유효성(UTF-8, `<urlset>`), URL 개수 ≈ 8,800, 샘플 후보/지역 URL 포함.
- robots.txt에 `Sitemap:` 절대경로·Disallow 정책 정확.

**롤백**: 두 신규 파일 삭제.

**DoD**: 사이트맵·robots 정상 노출, URL 전수 포함, 한도 이내, 빌드 영향 허용 범위.

**위험도**: 🟢 낮음 (신규 라우트, 기존 동작 불변).

### 🔴 SEO-3 — 검색엔진 등록·인증·제출  (P0, 운영 작업 / 코드 없음)

**목적**: 색인 요청·모니터링 채널 확보. 단기 승부의 실제 트리거.

**작업 (운영자 수동)**:
1. **구글 서치콘솔**: 도메인/URL 등록 → SEO-1 인증 메타로 소유권 인증 → `sitemap.xml` 제출 → 홈·시·도지사·주요 시군구 등 **고가치 URL 색인 요청**.
2. **네이버 서치어드바이저**: 사이트 등록 → 인증(`naver-site-verification` 메타) → XML 사이트맵 제출 → 수집 요청. (국내 노출 핵심.)
3. **빙 웹마스터**: 등록·사이트맵 제출(ChatGPT/Copilot 검색 백엔드 대비).
4. 발급된 인증 토큰을 SEO-1 자리(상수/env)에 주입하는 **소형 후속 PR** 1건.

**안전장치**: 코드 변경은 인증 토큰 주입(메타 only)뿐 → SEO-1과 동일하게 안전.

**검증**: 각 콘솔에서 "소유권 확인됨" + "사이트맵 읽힘(처리됨)" 상태. 며칠 후 색인 페이지 수 모니터링.

**롤백**: 인증 메타 제거.

**DoD**: 3개 콘솔 소유권 확인 + 사이트맵 접수 완료.

**위험도**: 🟢 없음(사이트 동작 무관).

### 🟡 SEO-4 — 메타데이터 사실 평문화 + 홈 메타 + per-page canonical  (P1)

**목적**: 제목·설명에 핵심 사실을 넣어 CTR·AI 인용을 높이고, 동적 페이지에 canonical 부여.

**변경 파일**: `app/candidates/[id]/page.tsx`·`app/districts/[id]/page.tsx`·`app/districts/[id]/compare/page.tsx`의 `generateMetadata`, `app/page.tsx`(홈 metadata 신규).

**구현 상세**:
- 후보 `description`: 현재 "공개자료·공약 — 중립 비교 자료" → **"기호 N · {정당} · 재산 {요약} · 전과 {유무/건수} · 출처 선관위 {기준일}"** 형태(있는 필드만). 직책별 분기로 **교육감은 정당 생략, 기초의원은 공약 문구 생략.**
- 지역 title: "{지역} 후보 목록" → 검색질의에 맞춰 "{지역} {직책} 후보 비교" 계열 검토(직책 혼재 지역은 일반형 유지).
- 각 동적 페이지 `alternates: { canonical: '/candidates/{id}' }` 등 정규 경로 지정 → `?sort=` 변형 흡수.
- 홈: `app/page.tsx`에 `metadata`(또는 `generateMetadata`) 추가 — 대표 설명 + 홈 전용 OG는 **기존 정적 `app/opengraph-image.png` 유지**(동적 이미지 재도입 금지, #70 §3).

**안전장치 — 건드리지 않는 것**:
- `generateMetadata`는 **순수 데이터 가공만**. 무거운 import·이미지 생성 호출 추가 금지.
- 누락 필드 접근 시 옵셔널 체이닝·기본값으로 **절대 throw하지 않게**(후보 6,712건 중 결측 다수). 빈 값은 문구에서 생략.

**검증**:
- 결측 케이스 표본(교육감/기초의원/재산 미수집 후보)에서 title·description이 깨짐 없이 생성되는지.
- 프리뷰에서 4개 경로 + 결측 후보 1명 직접 확인. 카카오/트위터 카드 미리보기 정상.

**롤백**: 해당 라우트 metadata 변경 revert(파일별 독립).

**DoD**: 사실 포함 메타 생성, 결측 무throw, canonical 부여, 프리뷰 정상.

**위험도**: 🟡 낮음~중 (동적 라우트의 metadata만, 렌더 본문 불변 — 단 결측 가드 필수).

### 🟡 SEO-5 — 크롤 도달성: 탐색형 인덱스  (P1)

**목적**: 사이트맵이 없어도 **링크만으로** 봇이 전 선거구·후보에 닿게 한다(크롤 견고성 + 내부링크 신호).

**변경 파일**: `app/districts/page.tsx` 강화 또는 `app/sitemap-index`성 인덱스 페이지 신규(예: `/districts`를 시·도 → 시·군·구 → 선거구 계층 목록으로). 후보/지역 페이지에 "같은 선거구 다른 후보 / 인접 지역" 링크 추가(컴포넌트 단위).

**구현 상세**:
- `/districts`(현재 주소검색 위주)를 **시·도 17개 → 각 시군구 → 선거구 링크**의 정적 목록으로 보강(서버 컴포넌트, `listDistricts` 순회). 주소검색 UX는 유지하고 그 아래 "전체 지역 둘러보기" 링크 섹션 추가.
- 지역 페이지: 이미 후보 링크 존재(유지). "이 시·군·구의 다른 선거구" 링크 추가 검토.
- 후보 페이지: "같은 선거구 다른 후보" 링크(이미 지역 경유 가능하나 직접 링크가 크롤·UX 모두 유리).
- 페이지네이션이 필요한 큰 목록은 링크 기반(쿼리 무한스크롤 금지 — 봇 도달 불가).

**안전장치 — 건드리지 않는 것**:
- 신규/보강 모두 **서버 컴포넌트 + 순수 loader**. `'use client'` 인터랙션(주소검색)은 기존 컴포넌트 재사용, 새 무거운 의존성 없음.
- 대량 링크 렌더의 페이지 무게·LCP 점검(시·도 단위 분할로 한 페이지 DOM 과대 방지).

**검증**:
- **크롤 도달성 테스트**: 홈에서 출발해 링크만 따라 임의 시군구의 임의 후보까지 N클릭 내 도달 가능한지 수동/스크립트 확인.
- 빌드·프리뷰 정상, 신규 목록 페이지 LCP 급증 없는지.

**롤백**: 인덱스 페이지/링크 추가분 revert.

**DoD**: 홈→전 선거구·전 후보 링크 도달 가능, 페이지 무게 허용, 프리뷰 정상.

**위험도**: 🟡 중 (신규 페이지·대량 링크 — 분할로 완화).

---

### 🟢 SEO-6 — 구조화 데이터(JSON-LD)  (P2)

**목적**: 검색·AI가 후보/목록/계층을 정확히 이해 → 리치결과·AI 인용 기반 마련. **toocheck의 정형 데이터와 궁합 최고.**

**변경 파일**: 각 페이지에 `<script type="application/ld+json">` 주입(서버 컴포넌트에서 직렬화). 공용 헬퍼 `lib/seo/jsonld.ts`(신규, 순수 함수).

**구현 상세** (있는 필드만, 빈 값 생략):
| 페이지 | 스키마 |
|---|---|
| 후보 상세 | `Person` (name, image, `memberOf`=정당, `jobTitle`=직책, `sameAs`) |
| 지역/비교 | `ItemList` (후보 순서 목록) |
| 전 페이지 | `BreadcrumbList` (홈 > 지역 > 후보) |
| 홈 | `WebSite`+`SearchAction`(사이트링크 검색창), `Organization`(운영주체) |
| 원칙 | `FAQPage` (GEO 최고 효율 — Q&A가 AI 인용 후보로 직결) |

**안전장치 — 건드리지 않는 것** ⭐️:
- JSON-LD는 **순수 문자열 직렬화** — 네이티브 의존성 0, #70 §3 위반 없음.
- **XSS/직렬화 안전**: `JSON.stringify` 후 `<`/`>`/`&` 이스케이프, `undefined`/`null` 필드 제거(빈칸 원칙).
- 렌더 본문·메타데이터 객체 불변. `<script>`는 서버 렌더 정적 문자열이라 hydration 영향 없음.

**검증**:
- Google Rich Results Test + Schema.org Validator로 오류 0(단, `Person`은 구글 리치결과 비공식 — 유효성만 확인, AI/타 엔진용).
- 콘솔 hydration 경고 없음. 프리뷰 4개 경로 + 결측 후보 정상.

**롤백**: JSON-LD 주입부 + 헬퍼 revert(페이지별 독립).

**DoD**: 스키마 유효, 결측 무오류, hydration 무경고, 프리뷰 정상.

**위험도**: 🟢 낮음 (순수 데이터 주입).

---

### 🟢 SEO-7 — GEO/AEO 콘텐츠 구조  (P2)

**목적**: AI 검색이 답을 추출·인용하기 쉽게 본문 구조를 다듬는다.

**변경 파일**: 후보/지역 페이지 상단 요약 컴포넌트, `/principles` FAQ 섹션(콘텐츠).

**구현 상세**:
- **직답 우선**: 후보 페이지 상단 40~60자에 핵심 사실을 평문 한 문장으로("○○○ 후보는 □□당 소속, 재산 N억, 전과 N건, 기준일 YYYY-MM-DD"). AI는 첫 문단에서 답 추출.
- **출처·기준일 가시화 강화**: 각 수치 옆 "출처: 중앙선거관리위원회 · {기준일}"(이미 부분 적용) 일관 적용 — 신뢰 신호.
- `/principles`에 자주 묻는 질문(FAQ) 본문 추가 → SEO-6의 `FAQPage` 스키마와 짝.

**안전장치**: 본문 콘텐츠/표현 추가 위주, 데이터·렌더 모델 불변. 빈칸 원칙 준수.

**검증**: 표본 페이지 가독성·결측 처리, 프리뷰 정상.

**롤백**: 콘텐츠 추가분 revert.

**DoD**: 직답 문장·출처 표기 일관, FAQ 노출, 프리뷰 정상.

**위험도**: 🟢 낮음.

### 🟠 SEO-8 — (선택·고위험) 동적 라우트 SSG/ISR 부분 전환  (P3)

> **D2에서 "추진" 결정 시에만.** #70이 의도적으로 동적으로 둔 경계를 건드리는 **유일한 작업** — 기본 권장은 **보류(동적 유지)**.

**목적**: 후보/지역 페이지를 정적 프리렌더(+ISR)하여 크롤 효율·LCP 개선.

**변경 파일**: 동적 라우트들에 `generateStaticParams` + `revalidate`.

**구현 상세 (점진·게이트)**:
- **한 번에 8,800개 프리렌더 금지.** 우선 시·도지사·교육감 등 **고가치 소수만** `generateStaticParams`로 시범 전환, 나머지는 `dynamicParams=true`로 온디맨드 유지.
- `revalidate` ISR로 데이터 갱신 흡수.
- **빌드 시간·메모리(13MB JSON 번들) 급증 여부를 프리뷰에서 측정** 후 확대.

**안전장치 — 가장 엄격** ⭐️:
- 별도 브랜치에서 **프리뷰 배포 전수 회귀**(소프트 내비게이션, share-card, 콘솔 에러 0). #64류 재발 시 즉시 중단·revert.
- 공유 카드 API·이미지 경로와의 상호작용 재확인(#70 §5).

**검증**: 프리뷰에서 전환 라우트 정적(○) 확인, 빌드 시간 허용, 4경로+결측 정상, share-card 정상.

**롤백**: `generateStaticParams`/`revalidate` 제거로 즉시 동적 복귀.

**DoD**: 시범 라우트 정적화 + 회귀 0 + 빌드 영향 허용. (확대는 후속 PR.)

**위험도**: 🟠 높음 (정적/동적 경계 변경) — 그래서 마지막·선택.

## 3. 권장 실행 순서 & 일정 감각

| 순서 | 작업 | 난이도 | 위험 | 비고 |
|---|---|---|---|---|
| 1 | SEO-0 결정 | — | — | D1·D2 확정 |
| 2 | SEO-1 색인 해제·메타 | 5~30분 | 🟢 | 즉시 |
| 3 | SEO-2 robots·sitemap | 1~2h | 🟢 | lastmod=기준일 |
| 4 | SEO-3 등록·제출 | 1h | 🟢 | **선거 전 단기 승부** |
| 5 | SEO-4 메타 사실화·canonical | 2~3h | 🟡 | CTR·GEO |
| 6 | SEO-5 크롤 도달성 | 반나절 | 🟡 | 링크 인덱스 |
| 7 | SEO-6 JSON-LD | 반나절 | 🟢 | 리치결과·AI |
| 8 | SEO-7 GEO 콘텐츠 | 2~3h | 🟢 | 직답·FAQ |
| 9 | SEO-8 SSG/ISR | 반나절+ | 🟠 | 선택·게이트 |

**현실적 기대치**: 2~4번을 지금 즉시 하면 구글에서 홈+주요 허브+일부 고검색 후보가 며칠 내 색인될 수 있다. 네이버 전면·8,800 전수 색인은 6/3 전엔 어렵다 — 장기 자산으로 5~8번까지 갖춘다.
